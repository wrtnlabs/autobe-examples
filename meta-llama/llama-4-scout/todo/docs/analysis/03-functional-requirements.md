## 1. Purpose and Scope
The purpose of this document is to outline the functional requirements for a Todo list application. The scope includes user authentication, Todo list management, and Todo item management.

## 2. User Actors
- **guest**: Unauthenticated user who can view public Todo lists.
- **user**: Authenticated user who can create, edit, and delete their own Todo items.
- **admin**: System administrator who can manage all Todo lists and users.

## 3. Functional Requirements
### Todo List Management
- Users can create new Todo lists.
- Users can view their own Todo lists.
- Users can edit their own Todo lists.
- Users can delete their own Todo lists.

### Todo Item Management
- Users can add new Todo items to their lists.
- Users can view Todo items in their lists.
- Users can edit Todo items in their lists.
- Users can delete Todo items from their lists.

## 4. Non-Functional Requirements
- The system shall respond within 2 seconds for user interactions.
- The system shall be available 24/7 with 99.9% uptime.

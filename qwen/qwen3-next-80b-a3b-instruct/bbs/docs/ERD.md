### `economic_board_citizen_sessions`

Stores JWT access and refresh tokens for citizen sessions, with creation
and expiration timestamps for session management.

This is a session table that maintains the authentication state of
citizens. Each record represents a single login session and contains
connection metadata to track where and when users logged in. Session
tables only maintain connection context and temporal information - they
do not store user profile data or authentication credentials.

Session records are created during authentication and invalidated during
logout or expiration. The expired_at field ensures sessions have limited
lifetimes for security, while the created_at field allows auditing of
login patterns.

This table is referenced exclusively by the authentication flow and is
never directly accessed by business logic or frontend interfaces.
Instead, users interact with the system using JWT tokens obtained from
these sessions.

Properties as follows:

- `id`: Primary Key.
- `economic_board_citizen_id`: The citizen who owns this session. [economic_board_citizens.id](#economic_board_citizens).
- `ip`
  > The IP address from which the session was initiated. Used for security
  > auditing and geolocation purposes.
- `href`
  > The URL path the user was visiting when initiating the session. Tracks
  > user entry point into the system.
- `referrer`
  > The previous web page that linked to the authentication endpoint. Used
  > for traffic analysis and security detection.
- `created_at`
  > Timestamp when this session was created. This field is mandatory for all
  > session records to enable auditing of login events.
- `expired_at`
  > Timestamp when this session expires. Sessions have a limited lifetime for
  > security. When expired_at is reached, the session is no longer valid and
  > the user must re-authenticate.

This table is exclusively used for citizen verification and is not shared

in administrative actions and enables forensic analysis of section
lifecycle. References to the original section (economic_board_sections)

### `economic_board_article_images`

### `economic_board_search_indices`

Full-text search index mapping article IDs to searchable text fields
(title and content). This table enables fast keyword matching on article
titles and content without scanning original article data. Each entry
represents one searchable text unit associated with an article. Maintains
referential integrity with articles table and provides optimized
full-text search capabilities through GIN indexing.

Properties as follows:

- `id`: Primary Key.
- `article_id`
  > Reference to the associated article in the economic_board_articles table.
  > [economic_board_articles.id](#economic_board_articles)
- `searchable_text`
  > Combined text content of the article title and body content for full-text
  > search capabilities. This field is indexed with a GIN index to enable
  > efficient fuzzy matching and text search operations

### `economic_board_search_tags`

Normalized, de-duplicated list of all tags used across articles. Each tag
is stored once with a unique ID, enabling efficient filtering and
reducing data redundancy. Tag text is stored in lowercase after trimming
whitespace to ensure case-insensitive matching. This table serves as the
canonical source for filtering articles by tag. No other component should
maintain a duplicate tag list.

Properties as follows:

- `id`: Primary Key.
- `text`
  > The normalized tag text. Stored in lowercase after trimming whitespace to
  > ensure case-insensitive matches during filtering. Maximum 50 characters.
- `created_at`: Timestamp when this tag was first created and inserted into the system.
- `updated_at`: Timestamp when this tag was last updated (if ever modified).

### `economic_board_search_article_tags`

Junction table defining the many-to-many relationship between articles
and tags. Each row represents an association between one article and one
tag, allowing filtering of articles by any combination of tags using AND
logic. This table eliminates data redundancy and enables efficient search
filtering while maintaining third normal form.

Properties as follows:

- `id`: Primary Key.
- `article_id`: References the article being tagged. [economic_board_articles.id](#economic_board_articles).
- `tag_id`
  > References the tag associated with the article. {@link
  > economic_board_search_tags.id}.

### `economic_board_search_results`

Cache table storing search query parameters and result metadata for
pagination and sorting. Each record represents one unique search query
with its parameters (keywords, sort direction, tags), result count, and
pagination metadata to avoid repeated query execution on identical
requests. This table enables fast retrieval of previously executed
searches by storing the combination of search criteria and results,
improving response times for repetitive queries on the same search
parameters.

Properties as follows:

- `id`: Primary Key.
- `article_id`
  > Reference to article that this search result is associated with. This
  > allows counting articles matching the search criteria. {@link
  > economic_board_articles.id}.
- `search_terms`
  > Full text search terms entered by the user. Stores the complete search
  > query string for matching against future requests. Must be non-null as
  > every search must have terms.
- `sort_direction`
  > Sorting direction for the search results. Must be either 'newest' or
  > 'oldest' as specified in search requirements. This value determines
  > whether results are ordered by creation date descending or ascending.
- `page`
  > Page number of the search results being cached. Represents the current
  > page of results (1-based indexing) as specified in the pagination
  > requirements.
- `per_page`
  > Number of results per page. Specifies how many articles are displayed per
  > page in the pagination system, typically 20 as required.
- `result_count`
  > Total number of articles matching this search query. Represents the total
  > count of results across all pages for this specific search criteria.
- `created_at`
  > Timestamp when this search result cache entry was created. Used for cache
  > expiration and analytics. Follows standard temporal field pattern and
  > uses server time (Asia/Seoul).
- `tag_filters`
  > JSON-encoded array of tag names used for filtering search results. Stores
  > multiple tags in string format to enable efficient tag-based filtering
  > without requiring junction table joins.

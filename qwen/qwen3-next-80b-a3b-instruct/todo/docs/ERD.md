### `todo_app_users`

Registered user accounts with email/password authentication credentials,
email verification status, and account security settings.

Stores identity information for authenticated individual users who can
create, read, update, and delete their own todo items. Each user has
exclusive ownership of their data with no access to other users'
information.

This actor table serves as the canonical identity record for the user
type in the system, with related session, password reset, and email
verification tables managing authentication workflows. The primary key is
a UUID for distributed system compatibility and security.

Users must verify their email address before their account becomes fully
active, and they can reset their password through a secure time-limited
email link.

Properties as follows:

- `id`: Primary Key.
- `email`
  > User's unique email address used for authentication and communication.
  > Must be unique across all users and follow standard email format.
- `password_hash`
  > Securely hashed password for authentication. Never stored in plain text.
  > Generated using bcrypt or equivalent secure algorithm.
- `email_verified`
  > Indicates whether the user has verified their email address. Initially
  > false upon registration; set to true after successful email verification
  > through the token system.
- `created_at`
  > Timestamp when the user account was created. Cannot be modified after
  > account creation.
- `updated_at`
  > Timestamp of the last update to the user account. Updated whenever the
  > user modifies any account details.
- `deleted_at`
  > Timestamp when the user account was soft-deleted. If null, the account is
  > active. Used to preserve data integrity while allowing account removal.

### `todo_app_user_sessions`

JWT session tokens for user authentication stored in httpOnly cookies,
with access token expiration set to 15 minutes.

Tracks the login sessions for authenticated users. Each session
represents a single device/browser login with precise connection context.

Sessions are append-only audit records - never modified or deleted. The
system automatically expires sessions after 15 minutes of inactivity (as
specified).

This table is managed exclusively by the authentication system during
login/logout flows, not through direct user interaction.

Does not store token contents, password hashes, or user credentials -
only connection metadata and lifecycle timestamps.

Properties as follows:

- `id`: Primary Key.
- `user_id`: The user's [todo_app_users.id](#todo_app_users) who owns this session.
- `ip`: Client's IP address from which the session was established.
- `href`: The URL from which the user initiated the login session.
- `referrer`: The previous web page from which the user navigated to this application.
- `created_at`: Timestamp when this session was created and authenticated.
- `expired_at`
  > Timestamp when this session will expire automatically. Fixed at 15
  > minutes after created_at as per specification. Sessions are invalidated
  > upon expiration and cannot be refreshed.

### `todo_app_user_password_resets`

Password reset tokens with 1-hour expiration for secure password recovery
workflow, invalidated after use.

Each password reset request generates a unique token that the user
receives via email. The token is valid for exactly 60 minutes and can
only be used once. After successful password reset, the token is
immediately and permanently deleted from the system. The system
automatically purges expired tokens during maintenance windows.

Tokens provide a secure alternative to password transmission, ensuring
that only users with access to the registered email can reset their
passwords. This mechanism complies with security best practices for
authentication workflows.

Properties as follows:

- `id`: Primary Key.
- `todo_app_user_id`: The user who requested the password reset. [todo_app_users.id](#todo_app_users).
- `token`
  > Unique random string token generated for password reset. This token is
  > sent to the user via email and must be presented to complete the reset
  > process. Tokens are 64-character alphanumeric strings.
- `expires_at`
  > Expiration timestamp for this password reset token. Tokens are valid for
  > exactly 60 minutes from creation time. After expiration, the token cannot
  > be used for password reset.
- `created_at`
  > Timestamp when this password reset request was generated. This is used
  > for expiration calculations and audit trail.
- `updated_at`
  > Timestamp when this record was last updated. Usually when the token was
  > used and before deletion.
- `deleted_at`
  > Soft delete timestamp to maintain audit trail while allowing temporary
  > data purging. Set to the timestamp when the token is successfully used
  > and deleted from the system.

### `todo_app_todo_items`

Personal task items owned exclusively by a single user. Each todo
represents a discrete unit of work that can be tracked to completion.

Stores individual todo items with strict ownership by a single user. Each
item has a unique ID, title, description, status
(pending/completed/archived), and timestamps for creation and updates.
The userId field links to the authentication agent's user table, ensuring
complete data isolation. Todo items are not shared between users and can
only be accessed, modified, or deleted by their owner.

This is the primary business entity of the Todo application, supporting
full CRUD operations with independent filtering and searching
capabilities.

Properties as follows:

- `id`: Primary Key.
- `user_id`: Owner of this todo item. [todo_app_users.id](#todo_app_users).
- `title`: Brief title for the todo item, maximum 255 characters.
- `description`
  > Detailed description of the todo item, maximum 10,000 characters.
  > Optional field for additional context.
- `status`
  > Current status of the todo item. Valid values: pending, completed,
  > archived.
- `created_at`: Timestamp when this todo item was created.
- `updated_at`: Timestamp of the last modification to this todo item.
- `deleted_at`
  > Timestamp when this todo item was logically deleted (soft delete). NULL
  > indicates active item.

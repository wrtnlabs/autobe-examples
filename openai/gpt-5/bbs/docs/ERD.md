### `civic_board_configurations`

System-wide configuration entries stored as independent key-value
records. Used to toggle features, define thresholds, or set URIs across
the platform. This table is intentionally decoupled from domain content
and identities to avoid dependency cycles. Managed primarily by
administrators through configuration UIs or scripts; referenced by
runtime services to read current settings. No foreign keys are declared
to other domains.

Properties as follows:

- `id`: Primary Key.
- `key`
  > Unique configuration identifier (e.g., "public_read",
  > "attachments.max_count"). Serves as the business key for lookups.
- `value_string`
  > String value for this configuration when applicable. Only one of the
  > typed value columns is expected to be used per row.
- `value_int`
  > Integer value for this configuration when applicable (e.g., numeric
  > limits).
- `value_double`
  > Decimal value for this configuration when applicable (e.g., thresholds or
  > ratios).
- `value_boolean`
  > Boolean value for this configuration when applicable (e.g., feature
  > toggle).
- `value_uri`
  > URI value for this configuration when applicable (e.g., callback URLs,
  > CDN endpoints).
- `description`: Human-readable explanation of the configuration purpose and usage.
- `effective_since`: Optional timestamp indicating when this configuration became effective.
- `created_at`: Creation timestamp (UTC).
- `updated_at`: Last update timestamp (UTC).
- `deleted_at`: Soft deletion timestamp for retention and operational safety.

### `civic_board_policies`

System policies governing platform behavior such as public-read,
moderation defaults, and feature switches. Each policy is an
independently managed record with an optional effective window. This
table is maintained by administrators and does not reference domain
content directly. Related changes are recorded in {@link
civic_board_audit_logs}.

Properties as follows:

- `id`: Primary Key.
- `policy_code`
  > Stable policy identifier (e.g., "public_read", "attachments.policy",
  > "report.duplicate_cooldown_hours"). Unique across the system.
- `name`: Human-friendly policy name for administrative UIs.
- `category`
  > Optional category for grouping related policies (e.g., "visibility",
  > "attachments", "reporting").
- `enabled`
  > Whether the policy is currently enabled. For value-carrying policies,
  > this indicates if enforcement is active.
- `value_string`: Optional string value carried by the policy (e.g., textual rule).
- `value_int`: Optional integer value (e.g., max counts, cooldown hours).
- `value_double`
  > Optional decimal value (e.g., size limits in MB with fractional
  > precision).
- `starts_at`: Optional start of the policy’s effective window (UTC).
- `ends_at`: Optional end of the policy’s effective window (UTC).
- `notes`
  > Administrative notes describing policy rationale or change context (not
  > shown to end users).
- `created_at`: Creation timestamp (UTC).
- `updated_at`: Last update timestamp (UTC).
- `deleted_at`: Soft deletion timestamp for retention and operational safety.

### `civic_board_audit_logs`

Append-only audit trail capturing security- and compliance-relevant
events across the system. Records the acting entity (user/admin/system),
optional session context, target reference, action name, outcome, and
request metadata. Designed for historical analysis and investigations;
not intended for direct user manipulation. This table provides the
system’s audit history for changes in [civic_board_policies](#civic_board_policies) and
[civic_board_configurations](#civic_board_configurations), as well as domain operations.

Properties as follows:

- `id`: Primary Key.
- `actor_type`

  > Stored as raw text to avoid cross-domain foreign keys.
- `actor_id`
  > Identifier of the actor, when applicable. Stored without a foreign key to
  > avoid domain coupling.
- `actor_session_id`
  > Identifier of the actor session when applicable. Stored without a foreign
  > key to avoid domain coupling.
- `action`
  > Business action name (e.g., "post.create", "comment.delete",

- `outcome`: Outcome summary (e.g., "success", "failure:rate_limited").
- `target_table`
  > Target table name when the action is scoped to a resource (e.g.,

- `ip`: IP address observed for the request context, when available.
- `href`: Full request URL, when available.
- `referrer`: Referrer URL, when available.
- `message`: Optional human-readable message or error context to aid investigations.
- `created_at`: Event creation timestamp (UTC).
- `updated_at`
  > Timestamp for any administrative update (e.g., redaction). Normally equal
  > to created_at for immutable entries.
- `deleted_at`: Soft deletion timestamp for retention or legal hold workflows.

### `civic_board_rate_limits`

Operational store for rate limiting windows and counters per actor and
scope. Managed by the system to enforce anti-abuse policies (e.g.,
post/comment/report creation, login attempts). Records are
created/updated within short time windows and expired/cleaned by
background tasks. No foreign keys to identities to avoid cross-domain
coupling.

Properties as follows:

- `id`: Primary Key.
- `scope`
  > Logical action scope for the rate limit (e.g., "post.create",
  > "comment.create", "report.create", "login.failed").
- `actor_type`
  > Actor type constrained by business logic (e.g., "user", "admin", "ip").
  > Stored as text to avoid cross-domain keys.
- `actor_id`
  > Identifier of the actor when applicable (e.g., user/admin). For IP-scoped
  > limits, this may be a surrogate or left null if not applicable.
- `window_started_at`: Start timestamp (UTC) of the rate limit window represented by this record.
- `window_ends_at`: End timestamp (UTC) of the rate limit window represented by this record.
- `count`: Number of actions performed during the window at the time of update.
- `limit`: Enforced maximum actions allowed during the window per actor and scope.
- `created_at`: Record creation timestamp (UTC).
- `updated_at`: Last update timestamp (UTC).
- `deleted_at`: Soft deletion timestamp to permit safe retention before purge.

### `civic_board_posts`

Discussion board posts (articles) authored by users. Contains the title,
body, and lifecycle status with publication and edit timestamps. Each
post is created by a [civic_board_users](#civic_board_users) actor. Optionally links to
the authoring [civic_board_user_sessions](#civic_board_user_sessions) for audit context without
risking content deletion when sessions expire (nullable +
onDelete:SetNull). Comments ([civic_board_comments](#civic_board_comments)) and
attachments ([civic_board_post_attachments](#civic_board_post_attachments)) reference this entity.
Visibility and moderation operate via status (Published/Hidden/Deleted)
and administrative records in [civic_board_moderation_actions](#civic_board_moderation_actions).

Properties as follows:

- `id`: Primary Key.
- `civic_board_user_id`: Author user's [civic_board_users.id](#civic_board_users).
- `civic_board_user_session_id`
  > Authoring session's [civic_board_user_sessions.id](#civic_board_user_sessions). Nullable and
  > set null on session deletion to preserve content.
- `title`: Post title. Business limits: 1–120 characters, trimmed, non-whitespace.
- `body`
  > Post body text. Business limits: 1–20,000 characters, plain text with
  > line breaks allowed.
- `status`
  > Lifecycle status of the post. Expected values: "Published", "Hidden", or
  > "Deleted". Used to control visibility and commenting eligibility.
- `published_at`
  > Publication timestamp recorded when the post becomes publicly visible
  > (Published).
- `edited_at`
  > Last content edit timestamp within the allowed edit window; null if never
  > edited.
- `created_at`: Creation timestamp (auditable).
- `updated_at`: Last update timestamp for this record (auditable).
- `deleted_at`
  > Soft deletion timestamp. Null when active; set when Deleted to support
  > retention/purge policies.

### `civic_board_post_attachments`

File attachments associated with posts. Attachments inherit visibility
rules from their parent [civic_board_posts](#civic_board_posts). Each row stores
immutable file metadata and storage URI. Only posts (not comments) can
have attachments. Uploaded by a user through a session for auditability.
Session link is nullable and set null on deletion to avoid unintended
content loss.

Properties as follows:

- `id`: Primary Key.
- `civic_board_post_id`: Parent post's [civic_board_posts.id](#civic_board_posts).
- `civic_board_user_id`: Uploader user's [civic_board_users.id](#civic_board_users).
- `civic_board_user_session_id`
  > Uploader session's [civic_board_user_sessions.id](#civic_board_user_sessions). Nullable and set
  > null on session deletion to preserve the attachment record.
- `uri`: Storage URI pointing to the attached file object.
- `original_filename`
  > User-facing original filename after sanitization; used for display and
  > duplicate prevention per post.
- `content_type`
  > MIME type detected/accepted (e.g., image/jpeg, image/png, image/gif,
  > application/pdf).
- `byte_size`
  > File size in bytes; used to enforce per-file and per-post total limits in
  > application logic.
- `image_width`
  > Image width in pixels if the attachment is an image; null for non-image
  > types.
- `image_height`
  > Image height in pixels if the attachment is an image; null for non-image
  > types.
- `created_at`: Attachment creation timestamp.
- `updated_at`: Attachment last update timestamp.
- `deleted_at`: Soft deletion timestamp for retention/purge handling.

- `deleted_at`: Soft deletion timestamp for retention/purge policies.

### `civic_board_reports`

User-submitted moderation requests (reports) across posts or comments.
Holds common report metadata such as reason, optional note, and workflow
status. Exactly one specialization row must exist in either {@link
civic_board_report_of_posts} or [civic_board_report_of_comments](#civic_board_report_of_comments) to
bind the report to its concrete target. Admins review these records and
create [civic_board_moderation_actions](#civic_board_moderation_actions) as resolutions. Reporters
may query their own reports via the specialization tables using the
reporter identity.

Properties as follows:

- `id`: Primary Key.
- `reason`
  > Reporter-selected categorical reason (e.g., Spam, Harassment, Off-topic,
  > Other). Business validation occurs at application level.
- `note`
  > Optional free-text note from the reporter, up to 500 characters per
  > business rules.
- `status`
  > Workflow state of this report such as "pending" or "resolved" for queue
  > management.
- `created_at`: Creation timestamp (UTC) when the report was filed.
- `updated_at`: Last update timestamp (UTC) for this report metadata.
- `deleted_at`
  > Soft deletion timestamp (UTC) when the report is removed from
  > public/admin queues but retained for policy retention.

### `civic_board_report_of_posts`

Specialization of [civic_board_reports](#civic_board_reports) that binds a report to a
specific post and captures the reporter identity and session for audit
and constraint enforcement. One-to-one with [civic_board_reports](#civic_board_reports).
Prevents duplicate reports by the same user on the same post via a
composite unique constraint.

Properties as follows:

- `id`: Primary Key.
- `civic_board_report_id`
  > Parent report's [civic_board_reports.id](#civic_board_reports). Enforces 1:1
  > specialization.
- `civic_board_post_id`: Target post's [civic_board_posts.id](#civic_board_posts).
- `civic_board_user_id`: Reporting user's [civic_board_users.id](#civic_board_users).
- `civic_board_user_session_id`: Reporting session's [civic_board_user_sessions.id](#civic_board_user_sessions).
- `created_at`: Creation timestamp (UTC) when this specialization was created.
- `updated_at`: Last update timestamp (UTC) for this specialization.
- `deleted_at`: Soft deletion timestamp (UTC) if this specialization is logically removed.

### `civic_board_report_of_comments`

Specialization of [civic_board_reports](#civic_board_reports) that binds a report to a
specific comment and captures the reporter identity and session for audit
and constraint enforcement. One-to-one with [civic_board_reports](#civic_board_reports).
Prevents duplicate reports by the same user on the same comment via a
composite unique constraint.

Properties as follows:

- `civic_board_user_session_id`: Reporting session's [civic_board_user_sessions.id](#civic_board_user_sessions).
- `created_at`: Creation timestamp (UTC) when this specialization was created.
- `updated_at`: Last update timestamp (UTC) for this specialization.
- `deleted_at`: Soft deletion timestamp (UTC) if this specialization is logically removed.

### `civic_board_moderation_actions`

Administrative resolution records for [civic_board_reports](#civic_board_reports).
Captures the acting admin and session with the chosen decision (Hide,
Delete, or No Action) and an optional note. Enforces a single resolution
per report via a unique FK, creating an immutable audit trail separate
from content state changes.

Properties as follows:

- `id`: Primary Key.
- `civic_board_report_id`: Resolved report's [civic_board_reports.id](#civic_board_reports). One action per report.
- `civic_board_admin_id`: Acting administrator's [civic_board_admins.id](#civic_board_admins).
- `civic_board_admin_session_id`: Administrator session's [civic_board_admin_sessions.id](#civic_board_admin_sessions).
- `decision`: Resolution outcome string such as "No Action", "Hide", or "Delete".
- `outcome_note`: Optional moderator note providing rationale for the decision.
- `created_at`: Creation timestamp (UTC) when the moderation action was recorded.
- `updated_at`: Last update timestamp (UTC) for this moderation action record.
- `deleted_at`
  > Soft deletion timestamp (UTC) if the action record is withdrawn
  > administratively.

### `civic_board_post_reactions`

User single-like reactions on posts. Each row represents at most one
reaction per (user, post) pair. The reaction is considered active when
not soft-deleted (deleted_at is NULL). Designed to support toggle
semantics by updating timestamps while preserving auditability.
References [civic_board_users](#civic_board_users) as the reacting actor and {@link
civic_board_posts} as the target content. Hidden or Deleted targets must
block new reactions at the application layer; self-like is prevented by
business rules.

Properties as follows:

- `id`: Primary Key.
- `civic_board_user_id`: Reacting user's [civic_board_users.id](#civic_board_users).
- `civic_board_post_id`: Target post's [civic_board_posts.id](#civic_board_posts).
- `created_at`: Creation timestamp when the reaction was first added (Like on).
- `updated_at`: Last update timestamp, including toggling operations.
- `deleted_at`
  > Soft deletion timestamp representing Like off toggle. NULL means the
  > reaction is currently active.

### `civic_board_comment_reactions`

User single-like reactions on comments. Each row represents at most one
reaction per (user, comment) pair. The reaction is active when deleted_at
is NULL, enabling toggle behavior without losing history. References
[civic_board_users](#civic_board_users) as the reacting actor and {@link
civic_board_comments} as the target comment. Hidden or Deleted targets
must block new reactions at the application layer; self-like is prevented
by business rules.

Properties as follows:

- `id`: Primary Key.
- `civic_board_user_id`: Reacting user's [civic_board_users.id](#civic_board_users).
- `civic_board_comment_id`: Target comment's [civic_board_comments.id](#civic_board_comments).
- `created_at`: Creation timestamp when the reaction was first added (Like on).
- `updated_at`: Last update timestamp, including toggling operations.
- `deleted_at`
  > Soft deletion timestamp representing Like off toggle. NULL means the
  > reaction is currently active.

### `civic_board_reaction_policies`

Administrative policy controlling whether reactions are enabled and under
what constraints. This table allows feature toggling and guardrails such
as self-like prohibition and per-user rate limits. It is managed
independently by admins and referenced by application logic at runtime.
Does not denormalize any computed counters. Related entities: users
[civic_board_users](#civic_board_users) for ownership context if needed; targets are
[civic_board_posts](#civic_board_posts) and [civic_board_comments](#civic_board_comments).

Properties as follows:

- `id`: Primary Key.
- `code`
  > Human-readable policy code identifier (e.g., "default"). Used to select
  > the active configuration.
- `enabled`: Whether reactions feature is globally enabled.
- `allow_on_posts`: Whether reactions are permitted on posts.
- `allow_on_comments`: Whether reactions are permitted on comments.
- `allow_self_like`
  > Whether self-like is permitted. Should remain false to satisfy product
  > rules.
- `max_reactions_per_user_per_day`
  > Optional cap on the number of reactions a single user may add per
  > calendar day. NULL means unlimited per this policy.
- `created_at`: Creation timestamp of this policy row.
- `updated_at`: Last update timestamp of this policy row.
- `deleted_at`
  > Soft deletion timestamp for deprecated or replaced policies. NULL means
  > active.

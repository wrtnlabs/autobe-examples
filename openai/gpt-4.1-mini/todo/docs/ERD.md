user identity for the multi-user todo application. Supports soft deletion
via deleted_at field, allowing account deletion. Acts as the root actor
entity for user-related operations and relationships.

### `multi_user_todo_todos`

Todos created by users with titles, optional descriptions, start and due
dates, completion status, soft deletion status, and timestamps. Each todo
belongs to exactly one user represented by multi_user_todo_users. Soft
deletion allows trash management. Completion status is a simple boolean
toggle.

Properties as follows:

- `id`: Primary Key.
- `multi_user_todo_user_id`: Owner user's [multi_user_todo_users.id](#multi_user_todo_users).
- `title`: Title of the todo item, required field.
- `description`: Optional detailed description of the todo item.
- `start_date`: Optional start date for the todo.
- `due_date`: Optional due date for the todo.
- `completed`: Completion status of the todo, true means done, false means not done.
- `created_at`: Timestamp when the todo was created.
- `updated_at`: Timestamp of the last update to the todo.
- `deleted_at`: Timestamp when the todo was deleted; null means not deleted (soft delete).

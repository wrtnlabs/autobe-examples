### `todo_app_system_settings`

Global system configuration key-value pairs used to control
platform-level behavior (feature toggles, operational thresholds, and
public defaults). Settings are administrated by platform operators and
can be queried for runtime configuration. Does not duplicate domain
prefixes. Temporal fields provided for audit and soft-delete.

- `id`: Primary Key.
- `key`

### `todo_app_todouser`

Authenticated end-user account for todoApp. Extended to include
authentication lifecycle and security fields required by business rules:
failed login counters, last failed timestamp, password reset tokens and
expiry, refresh token revocation marker, and optional MFA metadata. These
additions enable DB-level support for lockout (5 attempts/15min),
password-reset-driven token invalidation, and MFA opt-in while preserving
existing relationships to lists, sessions, invitations, collaborators,
and audit logs.

Properties as follows:

- `id`: Primary Key.
- `email`
  > Primary email address used for login and notifications; unique per
  > account.
- `password_hash`: Hashed password for authentication; never store plaintext.
- `display_name`: User-facing display name for search and UI.
- `is_verified`: Whether the user has verified their email address.
- `status`
  > Account lifecycle status (e.g., pending_verification, active, suspended,
  > pending_deletion, deleted).
- `failed_login_attempts`
  > Rolling count of recent failed login attempts. Application logic should
  > reset this on successful authentication or after lockout window
  > expiration.
- `last_failed_login_at`
  > Timestamp of the most recent failed authentication attempt; used to
  > enforce rolling lockout windows (e.g., 5 attempts within 15 minutes).
- `password_reset_token`
  > Opaque token issued for password reset flows. Null when no reset is
  > pending.
- `password_reset_expires_at`: Expiry timestamp for the password reset token.
- `refresh_tokens_revoked_at`
  > Timestamp after which previously issued refresh tokens are considered
  > revoked. Set when password changes or admin revokes sessions to force
  > re-authentication across devices.
- `mfa_enabled`
  > Whether multi-factor authentication is enabled for the account (opt-in).
  > Defaults to false.
- `mfa_secret`
  > Encrypted or reference to MFA secret/seed for the account. Nullable when
  > MFA is not enabled; secure storage and access controls required.
- `mfa_backup_codes`
  > Serialized, encrypted backup codes for MFA recovery; stored only when MFA
  > is enabled.
- `created_at`: Account creation timestamp.
- `updated_at`: Last account modification timestamp.
- `deleted_at`: Soft-delete timestamp; null when active.

Properties as follows:

- `todo_app_list_id`: Target list. [todo_app_lists.id](#todo_app_lists).

  > todo_app_todouser.id}.

- `message`: Optional human message included with the invitation.

### `todo_app_user_activity_logs`

Append-only activity log capturing user interactions and behavioral
events (login, logout, invitation responses, import/export requests).
Designed for auditing, behavioral analysis, and security investigations.
All actor FKs are nullable and use non-cascading semantics to preserve
history even when source objects are removed.

Properties as follows:

- `id`: Primary Key.
- `todo_app_todouser_id`
  > Actor user [todo_app_todouser.id](#todo_app_todouser). Nullable to retain activity logs
  > when user account is removed.
- `todo_app_todouser_session_id`
  > User session for this activity [todo_app_todouser_sessions.id](#todo_app_todouser_sessions).
  > Nullable to preserve records when session removed.
- `todo_app_list_id`
  > Optional list context for the activity [todo_app_lists.id](#todo_app_lists).
  > Nullable to preserve logs when lists are purged.
- `todo_app_task_id`
  > Optional task context for the activity [todo_app_tasks.id](#todo_app_tasks).
  > Nullable to preserve logs when tasks are purged.
- `activity_type`
  > Activity code (e.g.,
  > 'login','logout','invite_accept','import_request','export_request').
- `details`
  > Optional free-text or structured payload (stored as text) describing the
  > activity.
- `ip`: Source IP address for the activity.
- `href`: Optional associated URL or request href.
- `created_at`: Activity timestamp.
- `updated_at`: Record last-updated time for operational corrections.
- `deleted_at`: Soft-delete timestamp for the log entry (used rarely for redaction).

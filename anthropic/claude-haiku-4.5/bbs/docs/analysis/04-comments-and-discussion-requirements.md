# Comments and Discussion Requirements\n\n## Comments Overview\n\nComments are the primary engagement mechanism within the discussion board, enabling members to contribute their perspectives, insights, and responses to published articles on economic and political topics. The comment system is designed to be simple and straightforward, facilitating direct conversation without complex nested reply structures.\n\nTHE comment system SHALL support a flat, chronological discussion model where members post comments on articles, creating a linear conversation thread beneath each article. Comments form the foundation of user engagement and allow the discussion board to function as a true community discussion platform rather than a one-way content publication system.\n\n### Purpose and Value\n\nComments serve several critical purposes:\n- Allow members to share their viewpoints and analysis on published articles\n- Enable peer-to-peer discussion and knowledge exchange\n- Support rich media engagement through image and file attachments\n- Create evidence of active community participation and discussion quality\n- Provide feedback and diverse perspectives to article authors\n\n### Discussion Model\n\nTHE discussion system SHALL use a flat, chronological comment thread model without nested replies. All comments on an article are displayed in a simple sequence, organized by posting time. This keeps the discussion straightforward and prevents the complexity of deeply nested conversation trees.\n\n### Relationship to Articles\n\nComments exist exclusively within the context of published articles. WHEN a member posts a comment, THE system SHALL associate that comment with exactly one article. Comments cannot exist as standalone content—they are intrinsically linked to their parent article.\n\n---\n\n## Comment Creation Requirements\n\n### Eligibility and Permissions\n\nWHEN a guest user attempts to post a comment, THE system SHALL deny the action and display a message indicating that authentication is required. Only registered and authenticated members can create comments.\n\nWHEN a member attempts to post a comment on a published article, THE system SHALL process the comment creation request and proceed through validation.\n\n### Comment Submission Workflow\n\nTHE comment creation process SHALL follow these steps in order:\n\n1. **Initiation**: Member navigates to an article and initiates comment posting\n2. **Content Composition**: Member enters comment text and optionally selects file/image attachments\n3. **Validation**: System validates comment content against all rules (text length, format, spam checks)\n4. **Attachment Processing**: System validates all attached files (type, size, quantity)\n5. **Storage**: Upon successful validation, system stores the comment with current timestamp\n6. **Publication**: Comment becomes immediately visible on the article's comment thread\n7. **Confirmation**: Member receives confirmation that their comment was posted\n\n### Error Handling\n\nIF a comment submission fails validation, THEN THE system SHALL return a specific error message indicating which validation rule was violated. The system SHALL preserve the member's entered content so they can correct and resubmit without re-entering everything.\n\nIF file attachment validation fails, THEN THE system SHALL reject the comment submission and inform the member which attachment violated the rules (e.g., \"File size exceeds limit of 10 MB\").\n\nIF a member's internet connection is lost during comment submission, THEN THE system SHALL provide appropriate timeout handling and clear error messaging.\n\n### Creation Timestamps\n\nWHEN a comment is successfully created, THE system SHALL record the exact creation timestamp in UTC format. This timestamp is immutable and cannot be changed by any user, including moderators.\n\n---\n\n## Comment Attributes & Fields\n\n### Core Comment Structure\n\nEvery comment SHALL contain the following essential attributes:\n\n| Attribute | Description | Type | Requirements |\n|-----------|-------------|------|--------------|\n| Comment ID | Unique identifier for the comment | String (UUID) | System-generated, immutable |\n| Article ID | Reference to the parent article | String (UUID) | Required, immutable |\n| Author ID | Reference to the member who created the comment | String (UUID) | Required, immutable |\n| Author Name | Display name of the comment author | String | Required, sourced from user profile |\n| Content | The text body of the comment | Text | Required, 1-5,000 characters |\n| Created At | Timestamp when comment was created | ISO 8601 DateTime | Required, UTC timezone |\n| Updated At | Timestamp when comment was last edited | ISO 8601 DateTime | NULL if never edited |\n| Is Deleted | Soft deletion flag | Boolean | FALSE by default |\n\n### Author Information Display\n\nTHE system SHALL display the following author information with each comment:\n- Author's display name\n- Author's user ID (for traceability in discussions)\n- \"Member\" badge to indicate user type\n- Join date of the author (optional, if available)\n\n### Timestamps\n\nTHE system SHALL display both creation and modification timestamps for all comments:\n- Creation timestamp: Always shown to indicate when comment was originally posted\n- Modification timestamp: Shown only if the comment has been edited, with indicator \"(edited)\"\n- All timestamps SHALL be displayed in the member's local timezone when possible\n\n### Comment Status\n\nTechnically, comments have a publication status:\n- **Active**: Comment is visible to all users\n- **Deleted**: Comment is soft-deleted; content is hidden but comment record persists for audit purposes\n\nTHE system SHALL NOT display deleted comments to regular members but SHALL retain them in the database for moderation audit trails.\n\n---\n\n## Comment Attachments\n\n### Attachment Support\n\nWHEN a member posts a comment, THE member MAY optionally attach images and files to that comment using the same attachment system as articles. Comments support multiple attachments in a single post.\n\n### Supported File Types\n\nTHE comment attachment system SHALL support the same file types as the article attachment system:\n\n**Allowed Image Formats:**\n- JPEG (.jpg, .jpeg)\n- PNG (.png)\n- GIF (.gif)\n- WebP (.webp)\n\n**Allowed Document Formats:**\n- PDF (.pdf)\n- Microsoft Word (.doc, .docx)\n- Microsoft Excel (.xls, .xlsx)\n- Plain Text (.txt)\n- Markdown (.md)\n\n### File Size Limits\n\nTHE system SHALL enforce the following file size limits for comment attachments:\n\n| File Type | Maximum Size | Rationale |\n|-----------|--------------|-----------|\n| Individual Image | 10 MB | Support high-quality images |\n| Individual Document | 10 MB | Standard office document size |\n| Total Attachments Per Comment | 50 MB | Prevent excessive data per comment |\n\n### Attachment Quantity\n\nA single comment SHALL support a maximum of 5 attachments. IF a member attempts to attach more than 5 files to a single comment, THE system SHALL reject the additional files and display an error message.\n\nTHE system SHALL support:\n- Multiple image attachments in one comment\n- Multiple document attachments in one comment\n- Mix of images and documents in one comment\n\n### Attachment Validation\n\nWHEN a member attempts to attach a file to a comment, THE system SHALL:\n1. Verify the file extension matches an allowed type\n2. Verify the file size does not exceed individual limits\n3. Verify the total attachment size for the comment does not exceed 50 MB\n4. Scan the file for basic validity (e.g., images can be decoded, PDFs are readable)\n\nIF any validation check fails, THEN THE system SHALL reject the specific file and display the reason for rejection without rejecting the entire comment.\n\n### Attachment Display\n\nIn the comment display, attachments SHALL be shown in the following manner:\n\n- **Images**: Displayed inline within the comment, embedded below the comment text\n- **Documents**: Listed as downloadable links with filename and file size\n- **Thumbnail Generation**: Image attachments MAY show a thumbnail preview (optional optimization)\n- **Attachment Count**: The comment header SHALL indicate the number of attachments (e.g., \"2 attachments\")\n\n### Attachment Ownership and Access\n\nTHE member who posted the comment owns the comment attachments. Attachments can only be deleted by:\n1. The member who posted the comment (via comment editing/deletion)\n2. Moderators (via moderation functions)\n3. System administrators (via administrative functions)\n\nGuests can download and view attachments but cannot upload or manage them.\n\n---\n\n## Comment Editing & Deletion\n\n### Edit Capabilities\n\nWHEN a member selects to edit their own comment, THE system SHALL allow them to modify the comment text and its attachments.\n\nWHEN a member updates a comment's content, THE system SHALL:\n1. Save the new content\n2. Update the \"Updated At\" timestamp\n3. Mark the comment as \"(edited)\" for other viewers\n4. Preserve the original creation timestamp\n5. Display the edit timestamp to other users\n\n### Edit Time Window\n\nTHE system MAY optionally impose a time window for editing (e.g., 24 hours after posting), but FOR NOW, members SHALL have unlimited time to edit their own comments. This design decision keeps the system simple.\n\n### Attachment Editing During Comment Edit\n\nWHEN a member edits a comment, they MAY add new attachments or remove existing ones. THE system SHALL revalidate all attachments against the same rules as initial comment posting.\n\n### Deletion Capabilities\n\nWHEN a member deletes their own comment, THE system SHALL perform a soft deletion:\n1. Mark the comment as deleted in the database\n2. Hide the comment content from all user views\n3. Display placeholder text: \"[Comment deleted by author]\"\n4. Preserve the comment record for audit purposes\n5. Retain associated metadata for moderation review if needed\n\nWHEN a member deletes a comment, THE system SHALL also delete all associated attachments, removing them from storage.\n\n### Moderator Override\n\nWHEN a moderator deletes a comment due to policy violation, THE system SHALL perform deletion with additional logging. The deletion reason SHALL be recorded in the audit log.\n\nWHEN a moderator deletes a comment, THE system SHALL display: \"[Comment removed by moderator]\" to indicate content was removed for policy reasons.\n\n### Deletion Restrictions\n\nA member can only delete their own comments. IF a member attempts to delete another member's comment, THE system SHALL deny the action and display an authorization error.\n\n---\n\n## Comment Display & Threading\n\n### Display Order\n\nTHE system SHALL display comments in chronological order by default. The specific order SHALL follow this logic:\n\nWHEN retrieving comments for an article, THE system SHALL sort comments by creation timestamp in ascending order (oldest comments first). This creates a natural conversation flow where the earliest discussion appears first.\n\nTHE display order SHALL be: Comment 1 (oldest) → Comment 2 → Comment 3 → ... → Comment N (newest)\n\n### Comment List View\n\nTHE comment section of an article SHALL display as a simple list with the following elements for each comment:\n\n```\n┌─────────────────────────────────────────┐\n│ Author Name | Member | Posted: 2024-01-15\n├─────────────────────────────────────────┤\n│ [Comment text content...]               │\n│ [Attachments if present]                │\n├─────────────────────────────────────────┤\n│ Edit | Delete | Report (if own comment) │\n└─────────────────────────────────────────┘\n```\n\n### No Nested Replies\n\nTHE comment system SHALL NOT support nested replies or threaded sub-conversations. All comments exist at the same level. This keeps the discussion straightforward and prevents the complexity of deeply nested threads.\n\nIf a member wants to respond to another member's comment, they post a new comment that may reference or quote the original comment manually.\n\n### Comment Count and Visibility\n\nTHE article display SHALL show:\n- Total number of comments on that article\n- A comment section heading: \"Comments (X)\"\n- A prompt to members to post comments: \"Have something to add?\" or similar\n\nWHEN an article has zero comments, THE system SHALL display: \"No comments yet. Be the first to comment!\"\n\n### Deleted Comments Display\n\nWHEN displaying comments, IF a comment has been deleted, THE system SHALL:\n- Display a placeholder line: \"[Comment deleted by author]\" or \"[Comment removed by moderator]\"\n- NOT display the comment author name\n- NOT display the comment content\n- NOT display attachments\n- Preserve the comment's position in the thread for context\n\n### Pagination (if needed)\n\nIF an article has more than 50 comments, THE system MAY implement pagination to load comments in groups (e.g., 50 per page). However, for simplicity, the initial implementation SHALL load all comments on the article page.\n\n---\n\n## Comment Validation Rules\n\n### Text Content Requirements\n\nWHEN a member submits a comment, THE system SHALL validate the comment text against these requirements:\n\n| Requirement | Rule | Enforcement |\n|-------------|------|-------------|\n| Minimum Length | At least 1 character required | Reject if empty |\n| Maximum Length | Maximum 5,000 characters | Reject if exceeded |\n| No Whitespace Only | Comment cannot be only spaces/tabs | Reject if only whitespace |\n| No Null/Control Characters | Reject binary or control characters | Strip or reject invalid chars |\n| Encoding | Must be valid UTF-8 | Reject invalid encoding |\n\n### Character Encoding\n\nTHE system SHALL accept comments in any language and with any Unicode characters that are printable. THE system SHALL NOT restrict comments to ASCII only.\n\n### HTML/Script Prevention\n\nTHE system SHALL NOT allow HTML or script tags in comment text. IF a member enters HTML tags (e.g., `<script>`, `<img>`), THE system SHALL either:\n1. Escape the tags so they display as literal text: `&lt;script&gt;`\n2. Strip the tags before storage\n\nThis prevents script injection attacks while preserving the member's intended text.\n\n### Profanity and Content Filtering\n\nTHE system MAY optionally implement a profanity filter, but this is NOT required for the initial implementation. FOR NOW, comments are accepted as-is without content filtering, with moderation handled by human review.\n\n### Spam Prevention\n\nWHEN a member posts a comment, THE system SHALL check for spam patterns:\n\n**Rate Limiting**: \n- WHILE a member is within a 5-minute window, THE system SHALL limit that member to a maximum of 10 comments\n- IF a member exceeds 10 comments in 5 minutes, THE system SHALL reject the comment and display: \"Please wait a moment before posting again\"\n\n**Duplicate Detection**:\n- IF a member attempts to post a comment that is identical (character-for-character) to a comment they posted in the last 60 seconds, THE system SHALL reject the comment and display: \"This comment appears to be a duplicate of your recent post\"\n\n**Character Repetition**:\n- THE system SHALL reject comments where a single character is repeated excessively (e.g., \"AAAAAAAAAAAA\")\n- Threshold: More than 50 repetitions of the same character SHALL trigger rejection\n\n### URL Handling\n\nIF a comment contains URLs, THE system SHALL NOT automatically convert them to clickable links. URLs should be displayed as plain text. This keeps the system simple and prevents malicious URL distribution.\n\n### Mention/Tag Prevention\n\nFOR the initial implementation, THE system SHALL NOT support @ mentions or # hashtags. Mentions and tags create complexity and are not necessary for a simple discussion board.\n\n### Special Characters and Symbols\n\nTHE system SHALL accept all standard punctuation, mathematical symbols, currency symbols, and emoji. No special character restrictions apply beyond HTML/script prevention.\n\n### Validation Error Messages\n\nIF a comment fails validation, THE system SHALL provide specific error messages:\n\n| Validation Failure | Error Message |\n|-------------------|---|\n| Empty comment | \"Please enter comment text before posting\" |\n| Too long | \"Comment exceeds maximum length of 5,000 characters. Current length: X characters\" |\n| Spam - Rate limit | \"You're posting too quickly. Please wait before posting another comment\" |\n| Spam - Duplicate | \"This comment appears to be a duplicate of your recent post\" |\n| Invalid characters | \"Comment contains invalid characters. Please review and try again\" |\n\n---\n\n## Discussion Flow\n\n### Typical Member Discussion Workflow\n\n1. **Discovery**: Member reads a published article\n2. **Engagement**: Member decides to comment and share their perspective\n3. **Composition**: Member writes comment text and optionally attaches relevant images/documents\n4. **Posting**: Member clicks \"Post Comment\" button\n5. **Validation**: System validates and stores the comment\n6. **Visibility**: Comment appears immediately in the article's comment section\n7. **Social Interaction**: Other members read the comment and may post their own responses\n8. **Iteration**: Discussion continues as members post replies\n\n### Multi-Member Conversation Example\n\n```\nArticle: \"The Impact of Inflation on Small Businesses\"\n\nComment 1 (Member A):\n\"This is a critical issue. Small businesses face 20% increased costs monthly.\"\n[Posted: 2:30 PM]\n\nComment 2 (Member B):\n\"But inflation affects large corporations differently. Interest rates matter most.\"\n[Posted: 2:45 PM]\n\nComment 3 (Member C):\n\"I agree with both points. The government's policy response is key.\"\n[Posted: 3:15 PM]\n\nComment 4 (Member A):\n\"@Member B - you raise good points about interest rates. I hadn't considered...\"\n[Posted: 3:30 PM]\n```\n\nNote: Manual mentions (@) are supported through typing; the system doesn't have @mention features.\n\n### Comment Editing During Discussion\n\nWHEN a member edits their comment after other members have replied, THE edited comment SHALL display the \"(edited)\" indicator so other members know the content has changed since they read it.\n\n### Handling Deleted Comments in Context\n\nWHEN a comment is deleted and other comments reference it:\n- The referencing comments remain visible\n- Readers may not understand the reference to the deleted comment\n- This is acceptable and expected behavior in a simple discussion system\n\n### Discussion Closure\n\nTHE system SHALL NOT implement any automatic comment closure or locking. Articles and their comments remain open for discussion indefinitely unless:\n1. A moderator manually locks the article\n2. An administrator deletes the article\n\n### Comment Notification (Optional)\n\nTHE system MAY optionally notify a member when their article receives new comments, but this is NOT required for the initial implementation.\n\n---\n\n## Discussion Quality and Moderation Integration\n\n### Comment Moderation Access\n\nModerators can view all comments and have the ability to:\n- Delete comments that violate policies\n- View deleted comments for audit purposes\n- See comment edit history if tracked\n- Review reported comments\n\n### Reporting Capability\n\nWHEN a member encounters a comment they believe violates community guidelines, the member MAY report the comment to moderators (optional feature). THE system SHALL allow members to flag comments with a report reason.\n\n### Audit Trail\n\nTHE system SHALL maintain a log of all moderation actions on comments:\n- Deletion records (who deleted, when, optionally why)\n- Edit timestamps (when edited, who edited if tracked)\n- Report submissions (if implemented)\n\n---\n\n## Summary\n\nThe comments system provides a straightforward, flat discussion mechanism for members to engage with articles. By maintaining simplicity—no nested replies, no complex threading, no @ mentions—the system remains easy to understand and use while fostering meaningful community discussion. Combined with attachment support for rich media engagement, comments form the interactive heart of the discussion board platform.\n\n> *Developer Note: This document defines **business requirements only**. All technical implementations (architecture, APIs, database design, etc.) are at the discretion of the development team.*
